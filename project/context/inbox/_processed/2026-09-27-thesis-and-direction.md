# Geoff's thesis and direction (2026-09-27)

I have a hypothesis that.

- I need to develop towards a shared, persistent, deployed product manager agent that will help and eventually drive (with decreasing levels of steering) the major moves of a product manager at a large, complex, regulated enterprise.
- it is a hypothesis that there is a benefit to, over time, move from PMs using local instances of Claude code (or no ai at all) to builders using a harness that accretes trustworthy context to an increasingly complete and credible context layer, and leverage agents for to drive (with human steering) the moves we associate with product managers
- among the benefits: accumulating context and knowledge of governed, agent accessible stores (vs tacit knowledge captive in SMEs), persisting agent traces to understand and influence the level of ai fluency and agent delegation by users, over time drive less human effort to shaping and delivering decided intent, and more to tasks requiring creativity and critical thinking (esp applying empathy and business judgment to problem identification, applying taste to solution identification, and applying business and well managed rigor to accepting built solutions and releasing them to customers).
- there are many "beacons" (eg Ramp with Glass) making headway here — we need to do some competitive teardowns based on publicly available information on how they are approaching this.
- likely the majority of PM LOE at enterprises is likely mis spent: support for in market solutions, shaping intent, managing delivery and the iterative intent refinement loop that does not require creativity and judgment bus mostly re-discovering constraints, managing dependencies, etc
- this all rests upon a more complete sense than I have about the major product moves we should focus on, and a usable taxonomy about what those moves are, their inputs/processes/outputs, etc
- I think it is impractical to try to gather and record all of the human knowledge in the enterprise up front — and instead I think k nailing the architecture and workflows, and using iterative loops of agent orchestrated, human executed discovery and context validation/governance, will hill climb and context accrete to the state we need for full automation
- I don't know what the terminal state is for the PM—let's assume it is a fully synthetic agent; but there are a number of stops along the way from human PMs casually using Gemini, through PMs using standardized shaping skills in their own Claude code instance, to some deployed shared agent
- we need to figure out the path dependence in three axes: which tasks to start with, which deployment model to target for v1, how to think about the context ecosystem
- there is a natural interdependency with agentic DELIVERY of software. Let's assume that delivery happy via SDD, but needs well defined specs
